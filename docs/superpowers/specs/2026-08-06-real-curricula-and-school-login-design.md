# 실제 교육과정 데이터 반영 & 학교 기반 로그인 — 설계 문서

- **작성일**: 2026-08-06
- **목적**: 1단계 스캐폴드(플레이스홀더 2개 출판사, 교사/학생 공용 비밀번호)를 실제 데이터로 교체한다. 서천군 초등학교별 3학년 사회과 출판사 조사 시트에서 확보한 **실제 8개 출판사 교육과정**(대단원·학습주제·차시·교과서 쪽수·성취기준)과 **16개 학교의 학교별 로그인 체계**를 반영한다.

## 1. 배경

1단계 스캐폴드는 지학사·천재교과서 2곳의 플레이스홀더 데이터, "출판사 직접 선택" 화면, "교사/학생 공용 비밀번호 2개" 구조로 만들어졌다. 이번 단계에서 사용자가 제공한 구글 시트를 분석한 결과:
- 서천군 16개 초등학교가 실제로 쓰는 3학년 사회 교과서 출판사 목록
- 8개 출판사(천재교과서 박기범/김정인, 지학사 이건용, 동아 박영석, YBM 남성준, 아이스크림미디어 한춘희, 비상교육 설규주, 미래엔 전종한) 전체의 실제 진도표(대단원/주제/해당차시/전체차시/교과서 쪽수/성취기준)

를 확보했다. 이를 반영해 커리큘럼 데이터 모델, 내비게이션, 로그인 체계를 전면 개편한다.

## 2. 데이터 모델: 대단원 > 학습주제 > 차시

기존 `unit > subunit > lesson`을 시트 데이터에 맞춰 `unit(대단원) > topic(학습주제) > lesson(차시)`로 바꾼다.

- **대단원(unit)**: 시트의 "대단원" 컬럼. 1학기 2개("1. 우리가 사는 곳", "2. 일상에서 만나는 과거") + 2학기 2개("1. 사회 변화와 다양한 문화", "2. 옛날과 오늘날의 생활 모습")로 총 4개. `semester` 필드(1 또는 2)로 학기를 구분한다.
- **학습주제(topic)**: 시트의 "주제" 컬럼. 연속된 행이 같은 이름(끝의 "-1-"/"-2-" 접미사만 다름)을 가지면 하나의 학습주제로 묶는다. 예: "장소에서의 경험과 느낌 다양하게 표현해 보기 -1-"(6번째 행)과 "-2-"(7번째 행) → 학습주제 하나, 차시 2개. 순서는 시트/교과서 원래 순서를 그대로 유지한다.
- **차시(lesson)**: 학습주제 안의 개별 행. 필드:
  - `차시순서`, `전체차시`: **그 학습주제 안에서의 상대적 순서**(시트의 단원 전체 기준 해당차시/전체차시가 아님). 예: 위 예시는 1/2, 2/2.
  - `쪽수`: 교과서 쪽수 범위 문자열 (예: `"24~27"`)
  - `성취기준`: 문자열 배열. 0개(도입/정리 차시), 1개, 2개(두 성취기준을 함께 다루는 차시)가 모두 존재한다.

```json
// curricula/visang.json (실제 데이터 예시 일부)
{
  "publisherId": "visang",
  "publisherName": "비상교육(설규주)",
  "note": "2026 서천군 초등학교별 3학년 사회과 출판사 조사 시트에서 옮긴 실제 교과서 진도표입니다.",
  "units": [
    {
      "id": "visang-u1", "title": "1. 우리가 사는 곳", "order": 1, "semester": 1,
      "topics": [
        {
          "id": "visang-u1-t1", "title": "단원 주제의 학습 내용 예상하기", "order": 1,
          "lessons": [
            { "id": "visang-u1-t1-l1", "차시순서": 1, "전체차시": 1, "쪽수": "6~9", "성취기준": [] }
          ]
        }
      ]
    }
  ]
}
```

**출판사 8곳** (`publishers.json`): `chunjae-park`(천재교과서 박기범), `chunjae-kim`(천재교과서 김정인), `jihak`(지학사 이건용), `donga`(동아출판 박영석), `ybm`(YBM 남성준), `ecrimedia`(아이스크림미디어 한춘희), `visang`(비상교육 설규주), `mirae`(미래엔 전종한). 8곳 모두 데이터를 채우며, 실제로 서천 16개 학교가 쓰는 곳은 이 중 5곳(천재 박기범/김정인, 아이스크림미디어, 비상교육, 미래엔)이다.

**데이터 확보 및 검증 완료**: 시트 원문을 읽어 8개 출판사 전체(90~96행씩, 총 734행)를 원본 그대로 옮기고, 스크립트로 학습주제 그룹핑·상대적 차시순서 계산을 수행해 결과를 검증했다(행 수 일치, 다중 성취기준 파싱 확인, 그룹핑된 차시 순서 확인). 최종 JSON 8개 파일 + `schools.json` + `adminConfig.json` + `publishers.json`이 준비되어 있으며, 구현 단계에서 그대로 저장소에 복사한다.

## 3. 내비게이션 & 화면 구성

**로그인 후 첫 화면** = 대단원 목록. 기존 "출판사 선택 화면"(서천 읍면 지도 배경)은 완전히 삭제한다.
- 대단원을 클릭하면 그 아래에 **아코디언으로 학습주제 목록이 펼쳐진다**(페이지 이동 없음). 각 학습주제 옆에 "N차시" 뱃지를 표시한다.
- 학습주제를 클릭하면 **그 학습주제의 1번째 차시 상세 페이지로 바로 이동**한다.

**차시 상세 페이지** 레이아웃:
```
[대단원명 - 작게]
━━━━━━━━━━━━━━━━━━━━
   학습주제명 (가운데, 아주 크게)
━━━━━━━━━━━━━━━━━━━━
   1 / 2차시          p.24~27
   성취기준: [4사01-01] 주변 여러 장소에서의...

[◀ 이전 차시]              [다음 차시 ▶]

(서천 지역화 자료 카드들 - 기존과 동일한 ResourceCard/getTopicsForLesson 매핑 유지)

[이 차시 퀴즈] [이 학습주제 퀴즈] [이 대단원 퀴즈]
```
- 첫/마지막 차시에서는 이전/다음 버튼을 비활성화하거나 숨긴다.
- 기존 "소단원 목록 페이지"(SubunitListPage)와 "차시 목록 페이지"(LessonListPage)는 삭제하고 위 흐름으로 대체한다.
- 퀴즈 3단계 링크(차시/학습주제/대단원)는 모두 차시 상세 페이지에 둔다(소단원/차시 목록 페이지가 없어졌으므로).

**라우팅**:
```
/login
/p/:publisherId                              대단원 목록(아코디언)
/p/:publisherId/:unitId/:topicId/:lessonId    차시 상세
/quiz/:scope/:refId                           scope = lesson | topic | unit (기존 subunit → topic으로 이름 변경)
/admin/login
/admin
```
로그인 성공 시 학교에 매칭된 `publisherId`로 **자동 이동**한다. 사용자가 직접 출판사를 선택하는 화면은 없다.

## 4. 로그인 / 인증 구조 (Firebase 제거)

학교·관리자 비밀번호를 저장소 JSON으로 관리하기로 했으므로, **인증 경로에서 Firebase를 완전히 제거**한다. 실제 콘텐츠 관리(Firestore)가 필요해지면 나중에 별도로 다시 도입한다. `src/firebase.js`, `src/lib/accessConfig.js`, `.env.example`, GitHub Actions의 Firebase 시크릿, `firebase` npm 패키지를 모두 제거한다.

**`src/data/schools.json`** (16개 학교, 시트 순서대로 비밀번호 0101~1616 순번 2자리 반복):
```json
[
  { "id": "jangang-cho", "name": "장항초", "publisherId": "ecrimedia", "password": "0101" },
  { "id": "jangang-jungang-cho", "name": "장항중앙초", "publisherId": "chunjae-park", "password": "0202" }
]
```
(전체 16개 학교 데이터는 이미 준비되어 있음 — 구현 단계에서 그대로 복사)

**`src/data/adminConfig.json`**: `{ "password": "20262026" }`

**로그인 화면**: 학교이름(드롭다운, 16개 학교명 중 선택) + 학생이름(자유 입력, 검증 없음, 세션에만 저장) + 비밀번호(해당 학교의 `password`와 일치해야 통과) → 통과 시 세션에 `{schoolId, schoolName, publisherId, studentName}` 저장 후 `/p/:publisherId`로 자동 이동.

**관리자 로그인**: 비밀번호만 입력 → `adminConfig.json`의 값과 비교.

**교사/학생 구분은 없애고 "학교" 단위로만 관리**한다. **일반 사용자(학교로 로그인한 사람)와 관리자 모두 로그아웃 버튼을 가진다.**

## 5. 이전 최종 리뷰 이월 항목 처리

| 항목 | 처리 방식 |
|---|---|
| Firebase 초기화로 빈 화면 뜨는 문제 | §4에서 Firebase 제거로 자동 해결 |
| PublisherSelector의 접근성 문제(`role="listitem"` on button) | 그 화면 자체가 삭제되어 자동 해결 |
| 로그인 세션의 허술한 JSON 검증 | 로그인 로직을 새로 작성하며 함께 검증 강화 |
| 로그아웃 버튼 없음 | §4에서 일반 사용자·관리자 모두 추가 |
| QuizPage의 `questionCount={0}` 하드코딩 버그 | 수정 |
| QuizPage가 scope 값을 검증하지 않음 | 수정 |
| README에 "새 출판사/자료 추가법" 설명 없음 | 데이터 구조가 바뀌므로 이번에 새로 작성 |

## 6. 이번 단계에서 하지 않는 것 (Out of scope)

- 실제 서천 지역화 자료(`topics.json`/`mappings.json`/이미지·PDF·영상 자료) 채우기 — 기존 구조·플레이스홀더를 그대로 유지하고, 8개 출판사의 새 차시 ID 체계에 맞춰 **샘플 매핑 몇 개만** 다시 연결해 구조가 여전히 동작함을 보여준다.
- 교사/학생 콘텐츠 권한 차등화 — 여전히 향후 단계.
- 관리자 비밀번호/학교 비밀번호를 사이트 내에서 변경하는 UI — 여전히 JSON 파일 직접 수정.
- Firebase Storage 이미지 업로드, Firestore 콘텐츠 관리자 페이지 — 여전히 향후 단계.
- 세부 시각 디자인(색상·폰트 등) 다듬기 — 여전히 별도 frontend-design 패스.
