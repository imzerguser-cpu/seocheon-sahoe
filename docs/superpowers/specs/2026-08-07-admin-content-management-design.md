# 관리자 자료·퀴즈 관리 기능 — 설계 문서

- **작성일**: 2026-08-07
- **목적**: 관리자가 브라우저에서 직접 각 차시에 서천 지역화 자료(사진·영상 링크·QR)를 첨부하고, 퀴즈(객관식/OX/단답식)를 만들고 수정할 수 있게 한다. 학생이 보는 화면도 실제로 그 자료·퀴즈를 보여주고 풀 수 있도록 함께 개편한다.

## 1. 배경

2단계까지는 서천 지역화 자료(`src/data/topics.json`/`mappings.json`)와 퀴즈(`src/data/quizzes.json`)가 저장소에 커밋된 정적 JSON 파일이었고, 관리자 대시보드에는 실질적인 편집 기능이 없었다("파일을 직접 수정하세요" 안내만 존재). 이번 단계에서는 관리자가 실제로 콘텐츠를 관리할 수 있는 화면을 만든다.

사이트는 GitHub Pages에 정적으로 배포되므로, 브라우저에서 저장한 내용이 모든 사용자에게 보이려면 실시간으로 조회 가능한 저장소가 필요하다. 이를 위해 **Firestore를 콘텐츠 저장용으로만 재도입**한다 (인증 목적의 Firebase는 여전히 제거된 상태 — 이번에 추가하는 인증은 아래 §4에서 설명하는 전체관리자 1계정 전용).

## 2. 데이터 모델

### 2.1 `materials` 컬렉션 (서천 지역화 자료)

기존 `topics.json` + `mappings.json`의 역할을 문서 하나로 합친다. 하나의 자료가 여러 출판사의 여러 차시에 동시에 연결될 수 있다(N:M).

```json
{
  "id": "자동 생성",
  "title": "예: 서천 신성리 갈대밭 사진 자료",
  "usageNote": "활용법 설명 (선택, 빈 문자열 가능)",
  "resources": [
    { "type": "photo", "title": "갈대밭 전경", "url": "https://..." },
    { "type": "video", "title": "소개 영상", "url": "https://youtube.com/..." },
    { "type": "qr", "title": "체험학습 안내", "url": "https://..." }
  ],
  "lessonRefs": [
    { "publisherId": "ecrimedia", "lessonId": "ecrimedia-u1-t5-l1" },
    { "publisherId": "chunjae-park", "lessonId": "chunjae-park-u1-t6-l1" }
  ]
}
```

- `resources[].type`: `"photo" | "video" | "qr"`. `qr`은 `url`만 저장하고, 학생 화면에서 그 URL을 인코딩한 QR 이미지를 그 자리에서 생성해 보여준다(관리자가 QR 이미지 파일을 만들거나 올릴 필요 없음).
- `lessonRefs`가 비어있는(연결된 차시가 없는) 자료는 관리자 화면에서만 보이고 학생 화면 어디에도 나타나지 않는다.
- 차시에 연결된 자료가 하나도 없으면 그 차시의 자료 섹션 자체가 지금처럼 안 보인다(이미 구현된 "자료 없으면 숨김" 동작을 그대로 유지 — 모든 차시에 빈 자료 칸을 만들지 않는다).

### 2.2 `quizzes` 컬렉션

```json
{
  "id": "자동 생성",
  "scope": "lesson",
  "refId": "ecrimedia-u1-t5-l1",
  "type": "multiple-choice",
  "question": "우리가 사는 곳에서 볼 수 있는 장소가 아닌 것은?",
  "choices": ["학교", "시장", "우주정거장", "병원"],
  "answerIndex": 2
}
```

- `scope`: `"lesson" | "topic" | "unit"` (기존과 동일한 3단계).
- `type`: `"multiple-choice" | "ox" | "short-answer"`.
  - `multiple-choice`: `choices`(배열, 관리자가 직접 입력) + `answerIndex`(정답 인덱스).
  - `ox`: `answer`: `"O" | "X"`.
  - `short-answer`: `answer`: 정답 텍스트(문자열). 채점은 공백 제거 후 단순 문자열 비교.
- 해당 범위(scope+refId)에 문제가 하나도 없으면 차시 상세 페이지에 그 범위의 퀴즈 링크 자체가 안 보인다.

### 2.3 `adminConfig` 문서

```json
{ "password": "20262026" }
```

학교관리자 로그인 비밀번호. 정적 파일이 아니라 Firestore 문서로 바뀌어, 전체관리자가 로그인 후 값을 바꿀 수 있다.

### 2.4 기존 데이터 처리

`topics.json`/`mappings.json`에 있던 6개 항목은 1단계 때 만든 테스트용 자리표시자(제목만 있고 실제 사진·영상·QR 내용은 비어있음)이므로 폐기한다. `materials`/`quizzes` 컬렉션은 빈 상태로 시작하고, 관리자가 실제 자료를 앞으로 채워 넣는다. 8개 출판사 교육과정 데이터·16개 학교 로그인 데이터는 이번 변경과 무관하며 그대로 유지된다.

## 3. 학생이 보는 화면

- **차시 상세 페이지**: 자료 섹션을 `topics.json`이 아니라 Firestore `materials`에서 그 (출판사, 차시)에 연결된 문서만 읽어와 보여준다. 읽는 동안 짧은 로딩 상태를 보여주고, 실패 시 "자료를 불러오지 못했어요" 메시지를 보여준다.
- 퀴즈 링크(이 차시/학습주제/대단원)는 실제 문제가 있는 범위만 보인다.
- **퀴즈 페이지**: 지금은 문제 텍스트만 나열하는 자리표시자인데, 이번에 실제로 풀 수 있게 바뀐다.
  - 객관식: 보기를 클릭해서 선택.
  - OX: O/X 버튼.
  - 단답식: 텍스트 입력창.
  - 제출하면 그 자리에서 정답 여부를 보여준다. 점수나 풀이 이력은 저장하지 않는다(교사가 나중에 결과를 조회하는 기능 없음 — 학생 개인 연습용).

## 4. 관리자 인증 — 2단계 관리자

| | 학교관리자 | 전체관리자 |
|---|---|---|
| 로그인 방식 | 비밀번호(현재 `20262026`과 같은 단순 비번, Firestore `adminConfig`와 비교) | Firebase 이메일/비밀번호 실명 로그인, 계정 1개 |
| 할 수 있는 일 | 자료 관리, 퀴즈 관리 | 자료 관리, 퀴즈 관리 + 학교관리자 비밀번호 변경 |
| 용도 | 여러 사람이 동시에 같은 비번으로 로그인해서 협업으로 자료를 입력하는 현재 단계용 | 계정 보안이 필요해지면(자료 정리가 끝난 뒤) 학교관리자 로그인을 잠그는 역할, 지금 단계에서도 함께 만들어둠 |

- `/admin/login`에 탭 2개(학교관리자 / 전체관리자)를 만든다.
- 전체관리자 계정은 Firebase 콘솔에서 수동으로 1개 생성한다(README에 안내 작성, 비밀번호 재설정도 콘솔에서 직접).
- 학생/학교 로그인은 이번 변경과 완전히 무관하며 그대로 유지된다.

### Firestore 보안 규칙

```
match /materials/{doc} { allow read: if true; allow write: if true; }
match /quizzes/{doc}   { allow read: if true; allow write: if true; }
match /adminConfig/{doc} { allow read: if true; allow write: if request.auth != null; }
```

- `materials`/`quizzes`는 읽기·쓰기 모두 공개 — 이번 단계에서는 협업 편의를 위해 의도적으로 잠그지 않는다(재논의 대상 아님, 사용자가 명시적으로 선택). 실제 진입 통제는 앱의 학교관리자 비밀번호 화면에서만 이루어진다.
- `adminConfig`(학교관리자 비밀번호)만 Firebase 인증(=전체관리자)이 있어야 쓸 수 있다 — "전체관리자만 학교관리자 비번을 바꿀 수 있다"는 요구사항을 이 규칙이 실제로 보장하는 유일한 지점이다.
- 나중에 자료 정리가 끝나면 `materials`/`quizzes` 규칙도 `request.auth != null`로 바꿔 잠그는 것을 향후 과제로 남긴다(이번 범위 아님).

## 5. 관리자 화면 구성

- **관리자 대시보드**: "자료 관리", "퀴즈 관리" 버튼. 전체관리자로 로그인한 경우에만 "학교관리자 비밀번호 변경" 메뉴가 추가로 보인다.
- **자료 관리 화면**: 자료 목록(제목 + 연결된 차시 개수) → 새로 만들기/수정 폼(제목, 활용법, 자료 항목 여러 개 추가·삭제 — 각 항목은 종류(photo/video/qr) + 제목 + 링크, 연결할 차시를 출판사 → 대단원 → 학습주제 → 차시 순으로 골라 여러 개 담기) → 삭제.
- **퀴즈 관리 화면**: 범위(차시/학습주제/대단원) + 대상 선택 → 그 범위의 문제 목록 → 새 문제 추가 시 유형(객관식/OX/단답식) 선택 후 그에 맞는 입력폼 → 기존 문제 수정/삭제.
- **학교관리자 비밀번호 변경 화면**(전체관리자 전용): 새 비밀번호 입력 → Firestore `adminConfig` 갱신.

## 6. 기술적 변경 사항 요약

- `firebase`(Firestore + Auth) npm 패키지 재설치, `src/firebase.js` 재작성(Firestore + Auth 초기화, 지난번 삭제된 것과 달리 Auth는 전체관리자 로그인 전용으로만 쓰임).
- `.env.example`, GitHub Actions 배포 워크플로에 Firebase 설정값 시크릿 재도입.
- `src/lib/dataLoader.js`의 커리큘럼/학교 관련 함수는 지금처럼 동기(정적 JSON) 그대로 유지. 자료(`materials`)·퀴즈(`quizzes`) 관련 함수만 Firestore 비동기 읽기로 바뀌므로, 이를 사용하는 페이지(`LessonDetailPage`, `QuizPage`)에 로딩 상태가 추가된다.
- `src/lib/auth.js`에 전체관리자 세션(Firebase Auth 상태) 처리 추가, 기존 학교관리자 세션 로직은 유지하되 비밀번호 비교 대상이 정적 JSON에서 Firestore 문서로 바뀐다.
- README에 "Firestore 켜기", "전체관리자 계정 만들기", "Firestore 보안 규칙 배포" 안내 추가.

## 7. 이번 단계에서 하지 않는 것 (Out of scope)

- 학생 퀴즈 풀이 결과 저장/교사 조회 기능.
- 사진 파일 직접 업로드(Firebase Storage) — 사진도 링크만 입력받는다.
- `materials`/`quizzes` Firestore 쓰기 권한을 전체관리자로 잠그는 것(나중에 자료 정리가 끝난 뒤 별도로 진행).
- 학교/학생 로그인 방식 변경 — 완전히 그대로 유지.
- 관리자 화면에서 교육과정(대단원/학습주제/차시) 데이터 자체를 편집하는 기능 — 여전히 저장소 JSON 직접 수정.
